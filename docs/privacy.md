# Privacy

The parser only ever keeps: token/usage numbers, model names, timestamps,
tool/skill *names*, session titles, each session's working-directory path (the
project), PR links, and environment metadata (CLI version, git branch,
permission mode). For a subagent it also keeps its type and its short
description, the label Claude wrote when it started the subagent, cut to 120
characters; `--redact` removes it from a shared dashboard and no CSV carries
it. Message text, tool inputs/outputs, and prompt history are never kept —
enforced by a test (`tests/test_privacy.py`) that plants a distinct sentinel
string in every kind of record a transcript holds and asserts none of them
reaches the payload, the parse cache, `data.json`, the standalone dashboard or
any CSV.

There is one deliberate exception to "no message text": Claude Code's own
**usage-limit notices**. When a limit stops a request, Claude Code writes a
notice such as "You've hit your weekly limit · resets Oct 2 at 4am
(America/New_York)" into the transcript, on a record it flags `isApiErrorMessage`
with a rate-limit error. That notice is generated by Claude Code, not written by
you, and it is the only record of the allowance running out. The parser reads
its text only on records carrying both flags, keeps the limit type and reset
time, and drops the text immediately — `tests/test_limits.py` plants the
sentinel inside a notice and asserts it reaches neither the payload nor any CSV.

A few more narrow exceptions feed the [usage-health measures](usage-health.md).
Each is decided in memory, and only the result is kept:

- **Interrupts.** When you stop Claude mid-request, Claude Code writes its own
  fixed text, "[Request interrupted by user", into the transcript. The parser
  checks whether a record *starts with* that marker and keeps only the fact
  that it did. Nothing else in the record is looked at.
- **Check categories.** A shell command Claude runs is classified as a test,
  lint, build, commit or PR-creation run, and only that category is kept, so the
  dashboard can say whether a session that edited code ever ran a check on it.
  The command itself is never stored, cached or shown.
- **Slash commands.** A record that *starts with* Claude Code's own markup for
  a slash command, its output or a `!` shell command (`<command-name>`,
  `<local-command-stdout>`, `<bash-input>` and the like) is not counted as a
  prompt. Only the prefix is tested.
- **Response size.** From Claude Code 2.1.284 until 2.1.307 fixed it, most
  subagent responses were written to the transcript with only a placeholder
  output count, so their
  output is estimated from how much each response wrote (see
  [Cost estimates](cost.md#subagent-output-and-calls-the-transcripts-miss)).
  For every response the parser counts, in memory, the characters of its text,
  thinking and tool-call input, and the length of its thinking signature, and
  keeps only those two numbers. `tests/test_subagent_undercount.py` asserts
  the text never reaches the parsed facts.
- **Note edits.** An edited file's path is tested for being prose (`.md`,
  `.txt`, `.rst` and the like) or one of Claude Code's own files (anything under
  a `.claude` folder), so writing a memory file after the last test doesn't
  count as an unchecked edit. Only the yes/no is kept; the path is never stored.

The health measures otherwise read only metadata Claude Code writes alongside
the conversation: who sent a prompt (you, another session, a background task),
the permission mode it was sent in, why a tool call was refused, why the prompt
cache missed, whether a compaction was automatic or manual, and which *layers*
of instruction files were loaded (project, user, auto-memory). The paths and
contents of those files are never read. `tests/test_health.py` plants a
sentinel in prompts, a queued prompt, an interrupt, a shell command, edited file
paths, tool results and instruction files, and asserts it never reaches the
payload.

Outside the transcripts, two more things are read, and only for the export:
four plan fields from Claude Code's account cache (`~/.claude.json` — email,
seat tier, rate-limit tier, extra usage on/off; never account or organisation
ids, which a test asserts), and each project folder's git `origin` remote,
with any credentials embedded in the URL stripped before it is used.

The export also carries a `machine_id`: a random id made the first time you
export and kept in the tool's data folder (`~/.usage-lens`). It isn't derived from your
hostname, hardware or anything else on the machine, so it identifies nothing
beyond itself; it only lets a team merge tell your two machines apart.

**One network request, once a day: the price check.** The tool fetches
Anthropic's public pricing page
(`platform.claude.com/docs/en/about-claude/pricing.md`) to check its rate table
— a plain HTTPS GET carrying nothing about you or your usage, cached for a day,
with a 5-second timeout. Nothing is ever uploaded. Turn it off with `--offline`
on `serve.py` or `collect.py`, or `CLAUDE_USAGE_OFFLINE=1`. Team mode
(`serve.py --team`) doesn't make it.

The server only binds to `127.0.0.1` and rejects requests with a non-localhost
`Host` header, so it isn't reachable from the rest of your network. It also
refuses `/api/*` requests another site's page could make and forbids being
framed (see [cli.md](cli.md)). The parse cache is plain JSON rather than a
pickle, so a tampered cache file can't execute code on the next scan. Everything the dashboard renders is HTML-escaped —
session titles are model-generated from your own conversations, so they're
treated as untrusted text.

**Before sharing a `--static` build**, pass `--redact`. It replaces session
titles with ids, drops subagent descriptions, and aliases project paths, git
branch names and PR repositories/URLs — all of which otherwise carry absolute
filesystem paths and client or feature names. Skill, MCP server, tool and
subagent-type names are kept. `data.json` is never redacted.

**The CSV export is different, and deliberately so.** It identifies you by email
and includes session titles, full project paths, branch names and PR links,
because its whole purpose is letting a manager attribute cost to people and
projects. It is the one output of this tool designed to be shared with someone
else, so read
[What is in the export file](export.md#what-is-in-the-export-file) before you send one.
`--redact` does not apply to it; the export's own opt-out is `--no-titles`.
