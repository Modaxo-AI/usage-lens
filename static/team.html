Spend per active day

PersonSpendActive days Per active dayAgainst Anthropic’s benchmark

Anthropic reports about $13 per developer per active day on average, and under $30 for 90% of users across enterprise deployments (Manage costs). List price, not your invoice. Active days are the exact distinct days where the export carries them (schema 11) and the person used one machine. Exports carry day counts, not the days, so for two machines the days range from the busier machine’s to both added together (at most 7 a week); for older exports they are estimated from the export’s own total and each week’s project days (or, failing that, added and capped at the week’s days in the export window). Where the days aren’t exact the table shows “≈”, the days they can be between, and the per-day range they give; a person is marked above the 90th percentile only if even the most days possible leave them over it.

Habits by person

Each person's habits next to the team median, to see where Claude Code could help someone more. They are coaching signals, not a score or a performance measure: a long session can be the right call for big work, and experienced users interrupt more, not less. Tell your team you look at these before collecting exports; each person sees the same figures for themselves on their own Habits tab. Only the two shares with a sourced line are highlighted: Anthropic's /usage flags long context (here, requests over 500k tokens) and cache misses at 10% of recent usage (this tool's cold-cache column counts expiry misses only). Built from the habit columns in schema-7 exports; see docs/usage-health.md.

Tools Claude Code uses to manage its own work (tasks, schedules, plan mode, worktrees). Their errors are Claude Code's, not an integration to fix.

Tool calls that returned an error across the selected people, for anything called at least 20 times, most errors first: every MCP server that qualifies, then the built-in tools (more under “Show more”). MCP tools are grouped by their server. The People column names who hit errors, with how many. A refusal (a permission denied or a hook that blocked a call) isn’t an error (exports before schema 13 can’t tell them apart, and count them as errors; a note above says when that applies). A tool name that isn’t in Claude Code’s documented tool list and never succeeded (made up by the model, or not available) is left out, and an MCP tool name that never succeeded while its server’s other tools did is listed apart, not counted in the server’s rate; a real tool that fails every time stays. Our suggestion, not Anthropic's: a tool that fails often for everyone may be an integration or a permission worth checking.

Grouped by the repo each PR was opened in, from its own URL — not by the folder the session ran in, which is often a different repo. Session cost is the cost of the sessions that opened them, shared evenly when one session opened several; a PR whose export gave no session cost has none here. “?” or “not recorded” under “Opened from another folder” means the export didn’t say, not that there were none. Output by person

PersonPRsCost per PR Lines addedLines removedCost per 1k lines Spend with line data

PRs only count where Claude Code logged them. From schema 13 on, lines are counted per edit from what each Edit/Write result shows, on the day of the edit; a session with no edit, or from a Claude Code version that doesn’t write the diff, has none. Exports before schema 13 took Claude Code’s own counter, which has no date and may cover only part of a session, and the desktop app doesn’t always write it. Cost per 1k lines divides the whole cost of the sessions that recorded lines by lines added plus removed. The last column is that cost as a share of what all the sessions that started in the selected weeks cost in all (a session counts whole, in the week it started), so it can’t pass 100%. Blank means not recorded, not zero.
